================================================================================
GUIA COMPLETO DO SISTEMA DE GLOSSÁRIO — Plataforma Mendonça
================================================================================
Este documento explica, em detalhe, como o glossário funciona no projeto: o que
ele é, onde vive no código, qual é a estrutura de dados, como os termos são
destacados dentro do editor, como o menu de contexto funciona e todas as
maneiras de definir um termo (com os nomes exatos de classes CSS, divs, spans,
inputs, estados React e funções envolvidos).

--------------------------------------------------------------------------------
1. O QUE É O GLOSSÁRIO
--------------------------------------------------------------------------------
O glossário é um dicionário conceitual da plataforma. Cada verbete associa um
TERMO (palavra ou expressão) a uma DEFINIÇÃO. Existem duas camadas de glossário:

  1) GLOSSÁRIO GLOBAL (definitions.json)
     - Fica em:  src/data/definitions.json
     - Carregado em runtime a partir do arquivo JSON.
     - Vale para TODOS os documentos de todos os usuários.
     - Contém verbetes de Matemática, Cálculo, Física, Biologia, Química,
       História, Geografia, Filosofia, Sociologia, Linguagens e Redação.

  2) GLOSSÁRIO PERSONALIZADO DO DOCUMENTO (propriedade "glossary" do doc)
     - Fica dentro de cada NotebookDoc, na propriedade:
         glossary?: Record<string, GlossaryDefinition>
     - É salvo no banco (Supabase) na coluna JSONB "glossary" da tabela
       de documentos (ver supabase-schema.sql, linha 93).
     - Só vale para o documento (ou para o grupo de documentos) ao qual
       foi associado.

Durante a leitura/edição os DOIS glossários são mesclados em um único mapa, de
forma que os termos de ambos são destacados igualmente.

--------------------------------------------------------------------------------
2. ESTRUTURA DE DADOS (tipagem)
--------------------------------------------------------------------------------
Definição de um verbete (interface GlossaryDefinition) — definida em:
    src/data/disciplinesData.ts

    interface GlossaryDefinition {
      term: string;        // Nome de exibição do termo (ex.: "Logaritmo")
      definition?: string; // Significado conceitual (texto)
      example?: string;    // Exemplo ou analogia prática (opcional)
      category?: string;   // Matéria/categoria (ex.: "Matemática")
      imageUrl?: string;   // URL de imagem do conceito (opcional)
    }

O campo "glossary" de um documento é um Record cuja CHAVE é o termo em
minúsculas e o VALOR é um GlossaryDefinition. Exemplo real (definitions.json):

    "logaritmo": {
      "term": "Logaritmo",
      "definition": "Expoente ao qual se deve elevar uma base fixa...",
      "example": "Se 2³ = 8, então log₂(8) = 3.",
      "category": "Matemática"
    }

4. MESCLAGEM DOS GLOSSÁRIOS (src/lib/glossary.ts)
--------------------------------------------------------------------------------
Função principal:

    mergeGlossary(custom?: Record<string, GlossaryDefinition>):
      Record<string, GlossaryDefinition>

    - Inicializa um mapa vazio.
    - "Absorve" primeiro o GLOBAL_GLOSSARY (definitions.json).
    - Depois "absorve" o glossário personalizado do documento.
    - Para cada verbete insere DUAS chaves minúsculas:
        * a própria chave do verbete (trim + toLowerCase)
        * o valor de def.term (trim + toLowerCase)  -> serve de "alias".
    - A ordem é importante: o custom sobrepõe o global em caso de conflito.

Arquivo src/lib/glossary.ts, exportações:
    GLOBAL_GLOSSARY: Record<string, GlossaryDefinition>
        = definitionsData (JSON importado).

    isAlphaNumericChar(ch: string): boolean
        Retorna true se o caractere for letra/acentuada (\p{L}), número (\p{N})
        ou underscore. Usado para garantir que o termo corresponda a PALAVRA
        INTEIRA (não casar dentro de outra palavra).

    escapeRegExp(s: string): string
        Escapa metacaracteres de regex (usado ao montar o padrão de busca).

Exemplos de uso do mergeGlossary:
    BlockNoteDocEditor.tsx:157

5. DESTAQUE DOS TERMOS NO EDITOR (src/lib/glossaryPlugin.ts)
--------------------------------------------------------------------------------
É um Plugin ProseMirror (a engine de edição por baixo do BlockNote). Ele varre o
documento e, em tempo real, envolve cada ocorrência de um termo do glossário com
uma DECORAÇÃO INLINE. As IDEs/CFS usam isso para não alterar o texto real (é só
visual/interativo).

Partes do plugin:

  - glossaryKey = new PluginKey<GlossaryPluginState>('docGlossary')
    Chave única que identifica o estado e as transações do plugin.

  - GlossaryPluginState { terms, pattern, matches }
      terms: Record<string, GlossaryDefinition>
      pattern: RegExp | null       -> regex com TODOS os termos (OR).
      matches: GlossaryTermMatch[] -> lista de { from, to, term }.

  - buildPattern(terms)
      Ordena as chaves do MAIOR para o MENOR comprimento (termos compostos
      como "função exponencial" casam antes de "função"). Monta:
          new RegExp(`(?:termo1|termo2|...)`, 'giu')
      Flags: g (global), i (case-insensitive — destaca "LOGARITMO" com chave
      "logaritmo"), u (unicode).

  - computeGlossaryMatches(doc, terms, pattern)
      Percorre cada nó de texto do documento (doc.descendants). Para cada match
      do pattern, verifica o caractere ANTES e DEPOIS com isAlphaNumericChar;
      se os dois vizinhos NÃO forem alfanuméricos => palavra inteira => registra:
          { from: pos + m.index, to: pos + m.index + matched.length, term }
      O termo guardado vem de def.term (ou do texto casado).
      Só atravessa um nó de texto por vez, o que preserva negrito/itálico.

  - createGlossaryPlugin(): Plugin
      state.init  -> { terms: {}, pattern: null, matches: [] }
      state.apply -> Reage a metas (meta do glossaryKey):
         * { terms: {...} }  => reconstrói pattern e recalcula matches.
         * tr.docChanged OU { refresh: true } => recalcula sem mudar termos.
      props.decorations -> Cria DecorationSet inline para cada match:
          Decoration.inline(m.from, m.to, {
            class: 'doc-glossary-term',
            'data-glossary-term': m.term,
          })
        Resultado: cada ocorrência vira, na DOM, um <span class="doc-glossary-term"
        data-glossary-term="Termo">...</span>.

  - setGlossaryTerms(view, terms)
      view.dispatch(view.state.tr.setMeta(glossaryKey, { terms }));
      Envia os termos para o plugin recalcular.

  - refreshGlossaryDecorations(view)
      view.dispatch(view.state.tr.setMeta(glossaryKey, { refresh: true }));
      Força o destaque se atualizar sem trocar os dados.

Registro do plugin no editor (BlockNoteDocEditor.tsx:37-45):

      key: 'docGlossaryPlugin',

    });

    });

Aplicar os termos quando o editor monta (BlockNoteDocEditor.tsx:176-179):

9. CLICAR NUM TERMO JÁ DESTACADO
--------------------------------------------------------------------------------
Ao clicar (left click) em qualquer palavra destacada com a classe
.doc-glossary-term, o editor:
  1. Fecha o balão (glossaryTip = null).
  2. Chama onDefineGlossary(term) (BlockNoteDocEditor.tsx:545-554).
  3. O CadernoWorkspace recebe e passa o termo para o modal pré-preenchido
     (ver seção 10), permitindo EDITAR um verbete existente.

10. COMO DEFINIR UM TERMO (3 CAMINHOS QUE ACABAM NO MESMO MODAL)
--------------------------------------------------------------------------------
Todos os fluxos abrem o componente AddGlossaryTermModal.tsx.

CAMINHO A — Menu de contexto (rápido, dentro do editor):
  1. Clique com o BOTÃO DIREITO sobre a palavra ou selecione um trecho e dê
     direito sobre ele.
  2. No menu .doc-ctx-menu, clique no botão "Definir no glossário"
     (.doc-ctx-item .doc-ctx-define).
  3. O CadernoWorkspace executa (linha 1971):
        onDefineGlossary={(term) => {
          setInitialGlossaryTerm(term);
          setIsAddGlossaryOpen(true);
        }}
     e o modal abre com o CAMPO "Palavra ou Termo" já preenchido.

CAMINHO B — Clique no termo destacado:
  1. Clique sobre um termo já destacado (.doc-glossary-term).
  2. O editor chama onDefineGlossary (seção 9) => mesmo código acima.
  3. modal preenchido com o termo; se o verbete já existir no glossário do
     documento, os campos vêm preenchidos para edição.

CAMINHO C — Botão "Novo Termo no Glossário" (menu "•••" da barra do documento):
  1. No documento aberto, clique no menu de mais opções (o botão com ícone
     "•••" no cabeçalho do documento).
  2. No dropdown, item:
        <button className="w-full px-3 py-2 ... flex items-center gap-2">
          <BookmarkPlus className="w-4 h-4 text-purple-500" />
          <span>Novo Termo no Glossário</span>
        </button>
     (CadernoWorkspace.tsx:1917-1927)
  3. onClick => setIsAddGlossaryOpen(true); setIsMoreMenuOpen(false);
     modal abre com o termo vazio.

12. SALVANDO O TERMO (CadernoWorkspace.tsx, handleAddGlossaryTerm, linha 740)
--------------------------------------------------------------------------------
  const handleAddGlossaryTerm = (term, definition) => {
    const group = (selectedDoc.group || '').trim();

    // Novo mapa = glossário atual + termo novo
    const newGlossary = { ...(selectedDoc.glossary || {}), [term]: definition };

    const withTerm = (doc) =>
      doc.id === selectedDocId
        ? { ...doc, glossary: newGlossary }
        : { ...doc, glossary: { ...(doc.glossary || {}), [term]: definition } };

    // Atualiza o estado local (todas as disciplinas)
    setAllDisciplines(prev => prev.map(d => {
      if (d.id !== selectedDisciplineId) return d;
      return { ...d, documents: d.documents.map(doc => {
        if (!group) return doc.id === selectedDocId ? withTerm(doc) : doc;
        const sameGroup = (doc.group || '').trim() === group;
        return sameGroup ? withTerm(doc) : doc;
      })};
    }));

    // Se o documento pertence a um GRUPO, o termo vai para TODOS os docs do
    // grupo; senão, só para o documento atual.
    // Persiste no Supabase (se logado):
    if (userId) {
      const affected = (selectedDiscipline?.documents || []).filter(doc =>
        doc.id === selectedDocId ||
        (group && (doc.group || '').trim() === group));
      affected.forEach(doc =>
        saveDocument(userId, withTerm(doc))
          .catch(err => console.warn('Erro ao salvar glossário no Supabase:', err)));
    }
  };

  OBSERVAÇÃO IMPORTANTE: para o novo termo aparecer destacado NA HORA, o
  editor precisa re-mesclar o glossário. Isso acontece porque o prop
  "glossary" do BlockNoteDocEditor muda (Re-render) e o useEffect em
  BlockNoteDocEditor.tsx:176-179 re-executa setGlossaryTerms(view, glossaryMap).

--------------------------------------------------------------------------------
13. RESUMO DO FLUXO COMPLETO (do clique ao destaque)
--------------------------------------------------------------------------------
  1. Usuário abre documento -> CadernoWorkspace renderiza
     <BlockNoteDocEditor glossary={selectedDoc.glossary} ...>.
  2. BlockNoteDocEditor faz mergeGlossary(glossary) (global + do doc).
  3. Plugin ProseMirror (glossaryPlugin) recebe os termos via setGlossaryTerms
     e varre o documento (computeGlossaryMatches).
  4. match-> palavras inteiras recebem decoração inline:
        <span class="doc-glossary-term" data-glossary-term="Termo">Termo</span>
  5. Mouse move sobre o termo -> .doc-glossary-term:hover + balão glossaryTip
     (classe fixed z-[99999] ...).
  6. Novos termos: clique direito > "Definir no glossário" (ou clique no termo,
     ou menu "•••" > "Novo Termo no Glossário") -> AddGlossaryTermModal
     (classes w-full / rounded-[28px] ...) -> Salvar Significado ->
     handleAddGlossaryTerm salva no doc e no Supabase -> useEffect re-aplica
     as decorações.
